# Classic CarPlay capability audit

Baseline: rt-carplay `45b3133`, [LIVI `4451f8f`](https://github.com/f-io/LIVI/tree/4451f8f8b927032dd59708ab2f1591548410139e) (Lasse Heitgres, GPL-3.0-or-later and NOTICE), and [DiPlay `615b32c`](https://github.com/shihabal3amri/DiPlay/tree/615b32ce0b40cd0b99ce94ba23a512001553684f) (GPL-3.0). Reference behavior is source evidence. Hardware Pending means the corresponding iPhone or board behavior remains to be checked. ## Protocol boundaries

The initial `ui_night` and `map_night` flags represent separate phone UI and map appearance states. The shared `appearance_setting` is the Automatic, Light, or Dark preference encoded as 0, 1, or 2. LIVI sends the main UI UUID, integer appearance mode, and integer preference in `uiAppearanceUpdate`. Both references send a Boolean in the main map's `setNightMode` command. Socket writes establish delivery to the event transport. Visible changes must be verified on the phone. The host owns the environment-light decision and its own HMI theme.

Initial `streams=0` describes the first control SETUP. Subsequent audio SETUP, packet arrival/authentication and sink playback are distinct checkpoints. Volume feedback from the phone and gain applied by the host are also distinct. See [audio negotiation](audio-negotiation.md) and [audio routing](audio-routing.md) for the existing models.

The receiver is a single active-session owner. USB unplug, Bluetooth/Wi-Fi handoff, retry timing, remembered-phone priority and switching policy remain host responsibilities. Protocol teardown and repeated endpoint setup belong to the SDK. Use [lifecycle and ownership](lifecycle-and-ownership.md) for the call order.
